# Sub2API 与 kiro-rs 计费差异初步核对

采集日期：2026-10-10，北京时间约 04:49–05:00。仅只读核验生产配置、余额缓存、请求指标；未修改业务代码、生产配置或发起付费模型请求。Sub2API 数据来自用户截图，未访问其部署服务器或核验部署版本。

## 1. Kiro credits 被界面标为美元

kiro-rs 追踪的 `credits` 来自上游 `meteringEvent.usage`，单位为 credit（`src/anthropic/stream.rs:1660`、`src/admin/trace_db.rs:122`）。账号余额来自上游 getUsageLimits，服务端直接返回额度，没有美元换算（`src/admin/service.rs:1028`）；前端却硬编码 `$`（`admin-ui/src/components/credential-card.tsx:1337`、`:1355`、`:1356`）。

用户截图中的已用 `$724.91`、上限 `$1000` 应按 credits 理解，不是 724.91/1000 美元。现场余额缓存的该账号套餐为 KIRO PRO、额度 1000。

当日读取 https://kiro.dev/pricing/：Pro 为 $20/月、1000 credits；额外 credits 为 $0.04/credit。若按整包额度全部使用来均摊，则 724.91 credits 对应约 $14.4982；按额外 credits 单价估值为 $28.9964。这只是两种估值，不能当作实际发票、购号成本或认定这些用量均属超额。

## 3. Sub2API 最终零值未覆盖初始输入

只读审查公开仓库 Wei-Shaw/sub2api，固定 commit `3a6fd1c9db07203ca308aaba69e502bc1f35b307`，不代表用户当前部署版本。

- `backend/internal/service/gateway_upstream_response.go:1235`：message_delta 的 input_tokens 仅在 `v > 0` 时更新。
- `backend/internal/service/gateway_anthropic_passthrough.go:652`：同样条件。
- kiro-rs 普通流式 `message_start` 先发估算 input（`src/anthropic/stream.rs:1572`），最终 message_delta 再发送包含明确零值的缓存分摊结果（`:1325`）。

从上述公开源码原样抽取通用解析函数，以 Go 1.26.4 本地隔离运行：初始 36538，最终明确 input=0/output=22/write=9012/read=177367，解析后仍保留 input=36538。正值覆盖与缺失字段保留两个对照通过。输入事件是合成 fixture，不是历史请求的原始 SSE 抓包。

复现：`go run docs/deployment/2026-10-10/evidence/sub2api-zero-usage-repro.go`。输出见旁边 `sub2api-zero-usage-repro-result.json`。该复现证明公开源码缺陷，与现场症状吻合；用户部署源码与原始事件仍待核验。

修复应区分“字段缺失”与“字段明确为零”：字段存在、合法且非负时更新，缺失才保留旧值。应覆盖通用和 passthrough 两路径；不能仅把 kiro-rs 的零值伪造为 1。

## 7. 本地兼容修复（2026-10-10）

用户明确混合分组仅作计算参考，不要求价格对齐。目标为四类 token 互斥计量、按各自单价复算，再应用对应倍率；Kiro credits 独立表示上游额度，不转换为美元账单。

新增配置 `sub2apiUsageCompat`，默认 false。开启后普通 Anthropic 流的 message_start 输入和输出为零，最终 message_delta 继续发送完整用量，内部输入估算、缓存分摊与 trace 统计不变。这样最终未缓存输入为零时，下游不会残留开始阶段的输入估算。非流式与 /cc 缓冲流继续使用最终用量；/cc 的零输入开始事件已有回归覆盖。

限制：普通流若中断且最终 message_delta 未送达，下游可能少计。此开关解决已定位的零值兼容问题，不保证模拟缓存等同真实上游缓存，不修改历史账单或价格。

后台余额移除美元符号，显示 credits；追踪费用列改为 Credits。验证：`cargo test --no-default-features` 全部791项通过，`npm run build` 类型检查和构建通过，`git diff --check` 通过。全仓 `cargo fmt --check` 存在大量基线格式差异，未进行无关批量格式化。前端本地依赖由 npm 安装且未生成锁文件，尚未核验 Docker 的 Bun 冻结锁文件构建，也未做浏览器视觉验收。
